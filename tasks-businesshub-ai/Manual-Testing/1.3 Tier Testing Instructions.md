The Testing Pyramid integration and the centralized test reporting features have been successfully merged. Here are the comprehensive instructions for running and verifying the 3-Tier Testing strategy locally:

### Overall Execution

You can run the entire Testing Pyramid (Tier 1 and Tier 2 automatically, with Tier 3 configured) using the unified shell script from the project root:

```bash
./run_pyramid_tests.sh

```

> **Note:** This script includes pre-flight health checks to ensure your required databases (PostgreSQL on port 5432 and Redis on port 6379) are active before attempting any test execution.

---

### Tier 1: Unit Tests (The Base)

**Scope:** Fast, isolated tests for components, UI logic, API validations, and internal calculations.

#### Backend Execution (Pytest)

Tests are located in `backend/tests/test_tier1_unit.py`.

```bash
cd backend
source .venv/bin/activate
pytest tests/test_tier1_unit.py

```

* **What it covers:** JWT signing/verification algorithms, Pydantic validation failures (ensuring `ERR_VALIDATION_001` translations), AI prompt gateway parsing logic, and GST 18% calculation edge cases.

#### Frontend Execution (Karma/Jasmine)

Tests are located in `frontend/src/app/tier1.spec.ts`.

```bash
cd frontend
npx ng test --watch=false --browsers=ChromeHeadless --include=src/app/tier1.spec.ts

```

* **What it covers:** CRM Kanban card state changes, API Error handling parsing gracefully from Angular components, and LMS Markdown parser security (XSS prevention) validation.

---

### Tier 2: Integration & API Tests (The Middle)

**Scope:** Verifying database transactions, multi-tenancy rules, background workers, and API webhook contracts.

#### Backend Execution (Pytest)

Tests are located in `backend/tests/test_tier2_api.py`.

```bash
cd backend
source .venv/bin/activate
export DATABASE_URL="postgresql+asyncpg://postgres:postgres@localhost:5432/app-db"
pytest tests/test_tier2_api.py

```

* **What it covers:**
* **Tenant Isolation:** Ensures endpoints throw 403 or 404 when querying deals outside of the authenticated `X-Organization-Id` context.
* **Billing RBAC:** Confirms AI credit exhaustion correctly throws an `ERR_BILLING_001` error to block subsequent actions.
* **Celery Workers:** Integrates explicitly with the async CRM Lead Scoring task structure via isolated asyncio event loops.
* **Stripe Webhooks:** Verifies idempotency logic and signature validation routines.



---

### Tier 3: E2E Tests (The Top)

**Scope:** Browser-based automated flows mapping to critical paths.

#### Playwright Execution

Tests are located in `e2e/tests/critical_paths.spec.ts`. Because these require the actual backend and frontend servers to be independently active and serving traffic locally, they are configured to skip in headless sandboxes.

To run them locally:

1. **Start your Backend:**
```bash
cd backend && source .venv/bin/activate && uvicorn app.main:app --port 8000

```


2. **Start your Frontend:**
```bash
cd frontend && npx ng serve --port 4200

```


3. **Run the tests:**
```bash
cd e2e
export E2E_SERVER_URL="http://127.0.0.1:4200"
npx playwright test

```



* **What it covers:**
* **Onboarding & Billing:** Workspace generation, Stripe 3DS checkout simulation to the active dashboard.
* **CRM Journey:** Deals generation, filling lead forms, drag-and-drop state modifications to 'Qualified'.
* **LMS & AI Journey:** Markdown lesson uploads, AI Copilot Quiz generation parsing, and user enrollment pipelines.



---

### Viewing the Reports

All tests dynamically push HTML outputs and metrics to the root `reports/` folder:

* `reports/backend_report.html` & `reports/backend_coverage/` (Backend Suite)
* `reports/frontend_report.html` & `reports/frontend_coverage/` (Frontend Suite)
* `reports/e2e_report/` (Playwright Suite)
