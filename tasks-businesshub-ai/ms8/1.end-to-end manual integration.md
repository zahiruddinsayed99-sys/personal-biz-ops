### **Local E2E Integration Testing Guide: BusinessHub AI**

Hi team! Now that Modules 0, 1, 2, and 5 are fully integrated into the `develop` branch, we need to run a manual end-to-end (E2E) QA pass on our local machines. This will ensure our multi-tenant boundaries, billing locks, and AI pipelines are working perfectly together.

Before starting, ensure your local environment is running:

* **Database & Cache:** `docker compose up -d db redis` (Ensure PostgreSQL has the `pgvector` extension enabled).
* **Backend:** `uvicorn app.main:app --reload --port 8000`
* **AI Worker:** `celery -A app.core.celery_app worker --loglevel=info`
* **Frontend:** `npm start` (Angular development server).

Please follow these scenarios sequentially and report any errors.

---

### **Test Scenario 1: Onboarding, Auth & Core (Module 0)**

**Objective:** Verify tenant bootstrapping, JWT lifecycle, and basic isolation.

1. **Organization Registration:**
* Navigate to the Sign-Up page.
* Attempt to create an organization using an invalid slug (e.g., with spaces or uppercase letters). Verify it fails.
* Create a valid organization (slug must match `^[a-z0-9]+(?:-[a-z0-9]+)*$` and be 3–30 characters long).


* **Check:** Verify in your database that the User, Organization, and `TENANT_OWNER` role were created together.




2. **Session & Token Validation:**
* Log in to the application.
* Open your browser's Developer Tools (Network/Application tab).
* **Check:** Verify the access token is present (15-minute lifespan) and that the refresh token (7-day TTL) is stored securely as an `HttpOnly`, `SameSite=Strict` cookie.




3. **Logout & Revocation:**
* Click Logout.
* **Check:** Verify the Redis session key (`sess:{user_id}:{token_id}`) is immediately revoked and you can no longer access protected routes.





---

### **Test Scenario 2: CRM & Multi-Tenant Isolation (Module 2)**

**Objective:** Verify Kanban reactivity, team invitations, and cross-tenant data protection.

1. **Kanban Reactivity & Optimistic Updates:**
* Log back in and navigate to the CRM Deals pipeline.
* Create a new Deal and drag it from `LEAD` to `QUALIFIED`.


* **Check:** The UI should update instantly (optimistic update). Disconnect your backend server briefly, move a card, and verify the Angular Signal automatically rolls back the UI state when the backend fails.




2. **Team Invitations:**
* Go to Team Settings and invite a new test user to your organization.
* **Check:** Verify in the database that the invitation uses a one-way SHA-256 hashed token.




3. **Cross-Tenant Isolation Check (Crucial Security Test):**
* Create a second, completely separate Organization/User in an incognito window.
* Copy the UUID of a CRM Deal from the first organization.
* Attempt to access or modify that Deal via the API (using Postman/Swagger) using the second user's authentication token.
* **Check:** The API must return an `ERR_NOT_FOUND_001` (HTTP 404) error, **not** a 403, to prevent metadata scanning.





---

### **Test Scenario 3: AI Copilot & Background Tasks (Module 5)**

**Objective:** Verify asynchronous Celery processing, pgvector isolation, and UI polling.

1. **AI Lead Scoring:**
* Open a CRM Deal card that has some historical notes or activities.
* Click the **Score Lead** button.
* **Check:** Watch the Celery worker logs in your terminal. You should see the `crm.calculate_lead_score` task execute.


* **Check:** In the UI, verify the progress polling via the Angular Signal correctly resolves and updates the card with a 0-100 score and `intent_signals`.




2. **AI Draft Follow-Up:**
* Click the **Draft Follow-Up** button on the same card.
* **Check:** Verify a modal pops up with a context-aware email draft and the "Copy to Clipboard" function works.




3. **Vector Search Isolation:**
* Attempt an AI document query/search from the second organization created earlier.
* **Check:** Ensure results only include embeddings bound to that specific `organization_id` (enforced by PostgreSQL `pgvector`) and that unauthenticated searches throw `ERR_RBAC_001` (HTTP 403).





---

### **Test Scenario 4: Billing Guardrails & Soft-Locks (Module 1 & 5)**

**Objective:** Verify the system correctly halts operations when seat limits or AI credits are exhausted.

1. **Atomic AI Credit Deduction:**
* Check your organization's `ai_credits_used` in the database.
* Run the AI Lead Scoring or Draft Follow-Up tool a few times.
* **Check:** Verify the credits deduct successfully in the database via the atomic SQL query, and that race conditions don't allow double-spending.




2. **Triggering the Soft-Lock Overage (BR-PLT-002):**
* On a Free Tier organization, use the backend DB to manually set your active seat count to 4 (which exceeds the Free Tier limit of 3).


* Attempt to create a new CRM Deal or use the AI Copilot.
* **Check:** The API must freeze the write flow and immediately return an `ERR_BILLING_001` (HTTP 402) error.


* **Check:** Verify you can still *read* the CRM pipeline data (read-only access remains intact).
