### ⚖️ Who Can Do This Job Better: **Jules vs. Antigravity?**

Milestone 5 (Hybrid Slice) ke andar **deep database transactions, strict security logic (SHA-256 token hashing, RBAC 404/403 boundaries), aur complex UI state management (Optimistic UI rollback with Angular Signals)** shaamil hai.

1. **Jules (Recommended Winner for Milestone 5) 🏆**
* **Why:** Jules hamare system contracts, test-driven development (TDD) rules, aur strict Human-in-the-Loop workflows follow karne mein exceptionally precise hai. Wo asynchronous SQLAlchemy syntax, repository isolation, aur edge-case rollbacks ko bina code hallucinate kiye execute karta hai.
* **Best For:** Backend security pipelines, database constraints, aur deterministic integration tests.


2. **Antigravity**
* **Why:** Antigravity UI/UX velocity aur frontend structural setups (jaise Angular Kanban boards, scss styling, animations) mein tez ho sakta hai, lekin strict business logic ya cross-tenant edge cases (jaise `404` vs `403` return karna) mein kabhi-kabhi assumptions le leta hai.



> **Advise:** **Jules** ko assign karein. Agar aap chahein toh prompt ke header mein dono ka naam rakh sakte hain, lekin evaluation/execution ke liye Jules ka output zyada deterministic aur bug-free rahega.

### 1️⃣ Message to NotebookLM: Finalizedized Architectural Decision Log

Is block ko copy karke **NotebookLM** mein log kar dein:

```markdown
# Architectural Decision Record (ADR): Milestone 5 Finalized Hybrid Slice Blueprint
**Date:** August 2026  
**Subject:** Finalization of the "Path B + A-Lite Hybrid" Specification with Security & UX Refinements

### 1. Architectural Summary
We have finalized the Milestone 5 feature slice as a **Collaborative CRM Pipeline (Path B + A-Lite Hybrid)**. This iteration upgrades our initial user-seeding concept into a production-grade invitation engine seamlessly integrated with an async CRM Kanban pipeline.

### 2. Implemented Refinements over Base Proposal
1. **Zero-Leakage Horizontal Isolation (HTTP 404 vs 403):**
   * Cross-tenant queries failing `WHERE organization_id = :current_tenant_id` must return **HTTP 404 Not Found (ERR_NOT_FOUND_001)** rather than HTTP 403. This prevents metadata leakage regarding UUID existence across tenants.
   * HTTP 403 Forbidden (ERR_RBAC_001) is strictly reserved for Vertical Isolation/RBAC failures within the *same* tenant.
2. **Database Optimizations & Indexing:**
   * Standardized monetary field naming to canonical `value_amount` (Decimal/NUMERIC).
   * Enforced Composite Partial Index on `crm_deals(organization_id, stage) WHERE deleted_at IS NULL` for $<50\text{ ms}$ Kanban stage grouping.
   * Enforced Partial Unique Constraint on `invitations(organization_id, email) WHERE accepted_at IS NULL` to prevent invite spamming.
3. **Cryptographic Token Security (`token_hash`):**
   * Plaintext URL tokens are never persisted. Only a SHA-256 hash (`VARCHAR(64)`) is stored in `invitations.token_hash`. Verification compares hashed input against stored value during an atomic database transaction.
4. **Optimistic UI with Rollback (Angular 19/20 Signals):**
   * Kanban card drag-and-drop updates local Signal state immediately. If backend `PATCH /api/v1/crm/deals/{id}/stage` fails, the Signal store catches the error and automatically rolls the card back to its previous column with a toast notification.

```

### 2️⃣ Copy-Paste Prompt for Jules / Antigravity

Is complete prompt ko **Jules / Antigravity** ko hand off karein:

```markdown
USER_REQUEST:
We have successfully completed and verified Milestone 4 (Multi-Tenant Onboarding & User Services) on the 'develop' branch.

Your goal for Milestone 5 is to build the Collaborative Multi-Tenant CRM Deal Pipeline ("Path B + A-Lite Hybrid"). You will implement a production-grade team invitation engine, Async SQLAlchemy 2.0 CRM domain repositories with strict horizontal/vertical isolation, and connect them to an Angular drag-and-drop Kanban interface with optimistic UI rollback.

Please execute the following tasks:

1. GIT BRANCH & WORKFLOW
- Create and switch to a new local feature branch off 'develop' named exactly: track/5-crm-hybrid
- Follow strict Human-in-the-Loop guidelines: Do NOT attempt to push directly to 'main' or 'develop'. All deliverables must be prepared for a Draft Pull Request.
- All commit messages must follow the Conventional Commits specification (e.g., "feat(crm): implement async deal repository with multi-tenant RBAC scoping").

2. DATABASE DDL & MIGRATIONS (Alembic)
Create migrations for lowercase, plural `snake_case` tables with UUID v4 primary keys and soft deletes (`deleted_at`):
- `invitations`:
  * Columns: `id` (UUID), `organization_id` (UUID FK CASCADE), `email` (VARCHAR), `role` (VARCHAR, default 'DOMAIN_MEMBER'), `token_hash` (VARCHAR(64) — SHA-256 hash, UNIQUE), `expires_at` (TIMESTAMPTZ — 48 hr expiry), `accepted_at` (TIMESTAMPTZ, nullable).
  * Constraint: Partial Unique Constraint on `(organization_id, email) WHERE accepted_at IS NULL`.
- `contacts`:
  * Columns: `id` (UUID), `organization_id` (UUID FK CASCADE), `full_name` (VARCHAR), `email` (VARCHAR, nullable), `phone` (VARCHAR, nullable).
- `crm_deals`:
  * Columns: `id` (UUID), `organization_id` (UUID FK CASCADE), `contact_id` (UUID FK SET NULL, nullable), `owner_user_id` (UUID FK SET NULL, nullable), `title` (VARCHAR), `value_amount` (NUMERIC), `currency` (VARCHAR, default 'USD'), `stage` (VARCHAR, default 'LEAD'), `expected_close_date` (TIMESTAMPTZ, nullable).
  * Constraint: Composite Partial Index on `(organization_id, stage) WHERE deleted_at IS NULL`.

3. A-LITE: INVITATION ENGINE & SEEDING PIPELINE
- `POST /api/v1/organizations/invitations` (Requires permission `user:manage`, i.e., `TENANT_OWNER` or `TENANT_ADMIN`):
  * Generates a random URL-safe plaintext token, computes SHA-256 hash, persists `token_hash` to database, and returns the plaintext token in response.
- `POST /api/v1/auth/invite/accept` (Public API):
  * Inside an async ACID transaction (`async with db.begin():`), verify plaintext token via SHA-256 hash match (`WHERE token_hash = :hash AND expires_at > now() AND accepted_at IS NULL`), create `User` account, insert into `user_roles` junction table as `DOMAIN_MEMBER`, and mark `accepted_at = now()`.
  * Trigger immediate Redis eviction for permission cache: `org:{org_id}:usr:{user_id}:perms`.

4. ASYNC CRM REPOSITORIES & HORIZONTAL / VERTICAL ISOLATION
Implement `ContactRepository` and `CrmDealRepository` using native Async SQLAlchemy 2.0 select and execute syntax:
- **Zero-Leakage Horizontal Isolation:** Every query must enforce `WHERE organization_id = :current_tenant_id AND deleted_at IS NULL`. If a cross-tenant ID is queried, return **HTTP 404 Not Found ('ERR_NOT_FOUND_001')** — NEVER return HTTP 403 for cross-tenant lookups to prevent metadata leakage.
- **Vertical RBAC Isolation:**
  * `POST`, `GET`, `PATCH` require `crm:write` (granted to `TENANT_OWNER` and `DOMAIN_MEMBER`).
  * `DELETE` (soft delete) requires `crm:delete` (granted to `TENANT_OWNER` only; return **HTTP 403 Forbidden ('ERR_RBAC_001')** for `DOMAIN_MEMBER`).
  * `DOMAIN_MEMBER` users can view all shared organization deals but can only modify deals where they are assigned as `owner_user_id`. Modifying another user's deal must return **HTTP 403 Forbidden ('ERR_RBAC_001')**.

5. ANGULAR KANBAN BOARD UI WITH OPTIMISTIC ROLLBACK
In `frontend/src/app/features/crm-pipeline/`:
- Build a responsive Kanban Board displaying columns: `LEAD`, `QUALIFIED`, `PROPOSAL`, `WON`, `LOST`.
- Include a view filter toggle: "All Team Deals" vs. "My Assigned Deals".
- **Optimistic UI with Rollback:** Dragging a deal card between columns must instantly update the local Angular Signals state. If the outbound debounced request to `PATCH /api/v1/crm/deals/{id}/stage` fails, the Signal store must automatically revert the card to its original column and display an error toast.

6. INTEGRATION TESTING GATES (`backend/tests/test_crm_pipeline.py`)
Write comprehensive automated pytest tests asserting:
- Horizontal Isolation: Querying across tenants returns HTTP 404 (`ERR_NOT_FOUND_001`).
- Vertical Isolation: `DOMAIN_MEMBER` deleting any deal or modifying another user's deal returns HTTP 403 (`ERR_RBAC_001`).
- Invitation constraints: Duplicate active invites return HTTP 409 (`ERR_INVITE_001`); expired tokens return HTTP 400 (`ERR_TOKEN_001`).
- Full atomic rollback on failed invitation acceptance or invalid deal creation.

When complete, verify all tests pass locally (`pytest -v`), commit your work to 'track/5-crm-hybrid', and submit a Draft Pull Request for architectural review.

```
