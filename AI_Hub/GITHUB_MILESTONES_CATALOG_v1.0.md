# Purpose

This document defines the milestone strategy for BusinessHub AI.

Each GitHub Milestone represents one Feature Sprint and provides a measurable checkpoint for planning, execution and release tracking.

---

# Milestone Principles

- One milestone = One Feature Sprint
- Every GitHub Issue belongs to exactly one milestone
- Close the milestone only after the Sprint Definition of Done is satisfied
- Create the release after the milestone is completed

---

# Naming Convention

Format:

```
Sprint XX – <Feature Sprint Name>
```

Examples

- Sprint 01 – Repository Setup
- Sprint 02 – Development Environment
- Sprint 03 – Engineering Quality
- Sprint 04 – Authentication
- Sprint 05 – Organizations

# Completion Criteria

A milestone is complete when:

- All milestone issues are closed
- Pull requests merged
- CI pipeline passes
- Documentation updated
- Sprint completion report committed
- Release tag created

---

# Best Practices

- Keep milestone scope fixed once execution begins
- Avoid moving issues between active milestones
- Review milestone progress daily
- Archive milestone after release
