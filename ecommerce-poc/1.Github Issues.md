Here is a proposed GitHub milestone plan focused strictly on getting the application into "minimum good shape." This structures the work into logical phases, prioritizing critical blockers first so the core shopping flow is functional end-to-end.

### 🚩 Milestone 1: Core Functionality Fixes (MVP Blockers)

**Goal:** Ensure a user can successfully view a product, add it to their cart, and complete a basic purchase without hitting dead ends.

* **[Bug] `critical` Fix Product Image Rendering**
* *Description:* Replace the gray placeholder boxes on the catalog and product detail pages with actual product images.


* **[Bug] `critical` Fix "Add to Cart" on Catalog Page**
* *Description:* Wire up the primary "Add to Cart" button on the standard product cards so items are successfully passed to the cart state.


* **[Enhancement] `high-priority` Add Global Cart Navigation**
* *Description:* Implement a Cart icon/link in the top header (with an item count badge) so users can access their cart from any route.


* **[Enhancement] `high-priority` Cart Item Management**
* *Description:* Add basic "Remove" (trash can) and quantity update (+/-) functionality for line items on the `/cart` page.



---

### 🛒 Milestone 2: Checkout Confidence & Flow Refinement

**Goal:** Smooth out the user experience during checkout to prevent drop-offs and ensure accurate data collection.

* **[Enhancement] `medium-priority` Checkout Form Validation**
* *Description:* Enforce required fields on the `/checkout` page (asterisks) and add basic validation (e.g., valid email format, minimum pincode length) before allowing submission.


* **[Enhancement] `medium-priority` Visual Feedback on Add to Cart**
* *Description:* Trigger a toast notification or a brief animation on the cart header icon when an item is added, confirming the action to the user.


* **[Enhancement] `medium-priority` Order Confirmation Continuity**
* *Description:* Add a "Continue Shopping" button to the `/order-confirmation` page to return the user to the catalog, preventing a dead-end UI.


* **[Bug] `low-priority` Hide Admin Route in Public Nav**
* *Description:* Remove the "Admin" link from the global header navigation to separate the customer experience from store management.



---

### ⚙️ Milestone 3: Product Customization & Admin Safety

**Goal:** Fix the specific logic for the custom builder and ensure the admin dashboard is safe from accidental misclicks.

* **[Enhancement] `medium-priority` Enforce Custom Kit Selection Rules**
* *Description:* On the `/product/:id` page, keep the "Add Custom Kit to Cart" button visible but disabled until exactly 3 variations are selected.


* **[Enhancement] `medium-priority` Admin Action Safeguards**
* *Description:* Add a browser confirmation dialog (e.g., "Are you sure?") when an admin clicks "Cancel" or "Mark Delivered" on the `/admin` dashboard.


* **[Enhancement] `low-priority` Admin Dashboard Date Formatting**
* *Description:* Add a Date/Time column to the admin orders table to establish chronological order.

### Issue #8: [Feature] Implement Dark/Light Mode & Theme Color Selection

**Labels:** `enhancement`, `ui/ux`, `frontend`, `milestone-3`

#### Description

Allow users to personalize their shopping experience by toggling between dark and light modes, and selecting from a small palette of primary accent colors. The app should remember these preferences across sessions.

#### Technical Specifications

* **Tailwind Configuration:**
* Update `tailwind.config.js` to enable class-based dark mode (`darkMode: 'class'`).
* Define primary color utilities using CSS variables (e.g., `--color-primary`) so they can be swapped dynamically, rather than hardcoding specific Tailwind color classes (like `bg-pink-600`).


* **State Management (`ThemeService`):**
* Create an Angular service using `BehaviorSubject` or Signals to track the current mode (`light` | `dark`) and current theme color (e.g., `pink` | `violet` | `teal`).
* Sync these values with browser `localStorage` on initialization and on every change.


* **Angular Material Integration:**
* Ensure the `.dark-theme` class is applied to the root `<body>` or `<app-root>` element so Angular Material components (like the dialogs and snackbars) adjust their backgrounds and text colors accordingly.


* **UI Implementation:**
* Add a visual dropdown or icon group in the `HeaderComponent` (near the cart) containing a Sun/Moon toggle for dark mode and small colored circles for the theme selection.



#### Acceptance Criteria

* [ ] Header includes a visible toggle for Dark/Light mode and options for at least 3 primary brand colors (e.g., Default Pink, Violet, Teal).
* [ ] Toggling dark mode seamlessly updates the background, text, product cards, and checkout surfaces without rendering issues.
* [ ] Selecting a new theme color updates the primary buttons (like "Add to Cart"), active states, and header accents.
* [ ] Refreshing or closing and reopening the browser retains the user's selected mode and color preferences.
